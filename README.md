# Parts Manager 12.6.0

Коммерческая версия локального приложения для проценки автозапчастей.

## Что есть

- Проценка по артикулу.
- Умный подбор через AI с учётом активного автомобиля/VIN.
- VIN-декодирование через NHTSA.
- Подключение ROSSKO, BERG, ZAP PRO, AVD и собственного REST/JSON API.
- Нормализация предложений от разных поставщиков.
- Фильтры по цене, сроку и наличию.
- Сортировка: оптимальная, цена, срок, наличие.
- Корзина без ухода со страницы проценки.
- Яркая отметка «✓ В корзине» и количество.
- Оптимизация корзины.
- Ошибка/таймаут поставщика не создаёт демо-цену и не ломает общую проценку.
- Мастер добавления поставщика с обязательной проверкой API до сохранения.
- Секреты AI и BERG не хранятся в исходнике.
- Данные вынесены в `data/`, есть мягкая миграция старых JSON.

## Windows

Для коммерческого распространения используйте `installer.iss` через Inno Setup 6.x.
Инструкция: `INSTALL_WINDOWS.md`.

После установки приложение запускается через ярлык **Parts Manager**. Консоль не показывается, браузер открывается автоматически, а при занятом порте 8000 выбирается следующий свободный localhost-порт.

## Запуск из исходников

Python 3.10+:

```bash
python parts_manager.py
```

После запуска интерфейс открывается автоматически. Порт можно задать через `PARTS_MANAGER_PORT`, а автоматическое открытие браузера отключить через `PARTS_MANAGER_NO_BROWSER=1`.

## AI

Создайте переменную окружения:

```text
OPENROUTER_API_KEY=ваш_ключ
```

Для Windows PowerShell:

```powershell
$env:OPENROUTER_API_KEY="ваш_ключ"
python parts_manager.py
```

Для Linux/macOS:

```bash
export OPENROUTER_API_KEY="ваш_ключ"
python parts_manager.py
```

## Данные

По умолчанию приложение хранит JSON в `./data`:

- `suppliers.json`
- `vehicles.json`
- `settings.json`
- `cart.json`
- `cart_backup.json`

Можно задать отдельную папку через `PARTS_MANAGER_DATA_DIR`.

## Важное перед продажей

Это локальное desktop/web-приложение: сервер по умолчанию слушает только `127.0.0.1`.
Не публикуйте порт наружу без отдельной авторизации, HTTPS и сетевого контроля.

Перед коммерческим релизом также нужно:

1. заменить/отозвать все ранее засвеченные API-ключи;
2. указать реквизиты правообладателя и условия лицензии;
3. собрать установщик под Windows;
4. добавить собственный механизм лицензирования/активации, если он нужен бизнес-модели;
5. провести тесты реальных API поставщиков на каждом релизе.

## Заказы по e-mail

В версии 11.0.5 из корзины можно отправлять отдельные заказы каждому поставщику.

1. В карточке поставщика укажите **E-mail для заказов**.
2. В **Настройки** заполните SMTP-сервер, порт, шифрование, логин и пароль.
3. В корзине нажмите **«📧 Отправить заказы поставщикам»**.

Для каждого поставщика программа формирует отдельное письмо с артикулом, брендом, названием детали, количеством, текущей ценой и суммой. Поставщику также предлагается подтвердить актуальную цену и срок поставки.

## v11.0.5 — коммерческое ядро

Добавлены:
- Центр заказов и карточка заказа;
- статусы и история событий;
- e-mail и generic REST/JSON API-заказы;
- внешний номер заказа;
- защита от повторной отправки через историю заказа;
- SQLite-база для заказов, клиентов, платежей и финансовых операций;
- финансовый журнал, денежный поток, прибыль, дебиторка и кредиторка;
- карточки клиентов;
- печатная форма заказа с возможностью браузера «Сохранить как PDF»;
- фильтрация центра заказов;
- единое отображение отсутствующей информации как «Нет данных».

Для конкретного поставщика формат API заказа должен соответствовать его официальной спецификации. Универсальный REST-механизм не подменяет поставщик-специфичный checkout API.


## GitHub

Репозиторий обновлений настроен на `streetracingteamshop-cyber/partsmanager`.

Для публикации новой версии достаточно отправить в GitHub тег вида `v12.6.1`, `v12.6.2` и т. д. GitHub Actions автоматически создаст Release, а приложение сможет обнаружить его через **Настройки → Проверить обновления** или при запуске.

Важно: репозиторий на GitHub должен содержать `parts_manager.py` в корне проекта.

## 12.6.0 — автообновление и диагностика поставщиков

- Добавлено автообновление из последнего GitHub Release.
- В **Настройки → Автообновление из GitHub** можно указать `owner/repository` и включить/выключить автоматическую проверку при запуске.
- Ручная проверка доступна через **Проверить обновления**.
- Данные приложения не хранятся в GitHub-архиве и не перезаписываются при обновлении.
- При проценке теперь отображаются поставщики, которые не ответили API, с текстом ошибки. Это позволяет сразу понять, почему в результатах виден только один поставщик.
- Если поставщик API не отвечает, приложение по-прежнему пытается показать последний импортированный прайс этого поставщика.

## GitHub Releases и автообновление Windows

Для публикации новой Windows-версии используйте тег вида `v12.6.1`, `v12.6.2` и т. п. GitHub Actions автоматически:

1. определит версию по тегу;
2. скачает 64-битный embedded Python 3.13;
3. подставит номер версии в приложение и Inno Setup;
4. соберёт `PartsManager-Setup-X.Y.Z.exe`;
5. создаст GitHub Release и прикрепит установщик.

Установленная Windows-версия PartsManager проверяет последний опубликованный Release. Если найдена более новая версия, приложение скачивает `.exe` установщика и запускает тихое обновление. Пользовательские данные хранятся отдельно от каталога установки и не удаляются при обновлении.

Для первого теста после загрузки workflow можно создать тег `v12.6.1` и проверить вкладку **Actions**. Если сборка завершилась успешно, установщик появится в **Releases → Assets**.
